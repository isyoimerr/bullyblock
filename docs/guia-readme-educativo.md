# Guía para README y presentación de repositorios educativos

## Objetivo

Un repositorio educativo debe leerse como una propuesta clara, profesional y comprensible para estudiantes, docentes, evaluadores y stakeholders.

## Lógica recomendada

### 1. Empieza con una imagen real del producto

- La primera imagen debe ser la captura del landing o de la pantalla principal real.
- No usar banners genéricos si ya existe una vista real del producto.
- El README debe abrir con lo que el usuario ve en la app.

### 2. Coloca el enlace de la app arriba

- Debe quedar visible desde el inicio del README.
- El visitante debe saber que el producto ya está desplegado y funcionando.
- Es ideal poner un bloque tipo: "Demo en vivo" + URL.

### 3. Explica el problema y la solución en pocas líneas

- Qué problema resuelve la app.
- Qué impacto tiene en la institución.
- Qué valor tiene para estudiantes y personal escolar.
- Frase clave: no solo reportar, sino acompañar y ordenar la respuesta.

### 4. Muestra la arquitectura de roles

- Estudiante
- Docente
- Psicorientación
- Admin

Cada rol debe tener una descripción breve, clara y enfocada en su responsabilidad dentro del flujo institucional.

### 5. La galería debe explicar cada pantalla

No basta con poner imágenes amontonadas.

Cada bloque debe tener:
- una imagen grande,
- un encabezado corto,
- y una explicación clara de qué es esa pantalla y para quién sirve.

Ejemplo:
- Landing / bienvenida
- Estudiante: pedir ayuda y reportar
- Docente: seguimiento y acompañamiento
- Psicorientación / administración
- Estado crítico / alerta

### 6. Mantén una narrativa por secciones

El README debe leerse como un recorrido lógico:

1. Qué es
2. Para qué sirve
3. Quiénes participan
4. Cómo se ve
5. Cómo funciona
6. Cómo está desplegado

### 7. Es mejor claridad que densidad

- Un README útil no necesita estar saturado.
- Debe ser legible, ordenado y entendible para alguien ajeno al proyecto.
- La explicación del flujo importa más que apretar todo en pocas líneas.

### 8. El lenguaje debe ser del proyecto

Si el proyecto es educativo y está en español, el README debe estar en español.
Esto mejora la comprensión, la apropiación y la presentación ante docentes, estudiantes y evaluadores.

## Estructura óptima para un repo educativo

- Hero visual con imagen real
- Botón de demo en vivo
- Propósito del proyecto
- Roles del sistema
- Galería con explicación por pantalla
- Stack tecnológico
- Institución / contexto
- Contribuidores
- Cómo correrlo
- Estructura del repo
- Licencia institucional

## Regla práctica

Si alguien abre el repo y entiende:
- qué es el proyecto,
- para quiénes sirve,
- cómo funciona,
- y cómo se ve,

entonces el README cumple su objetivo.

## Frase guía para repos de este tipo

"La plataforma ayuda a estudiantes a reportar situaciones de riesgo sin miedo y permite a la institución responder con empatía, orden y claridad."

## Observación importante

El README debe sentirse como una presentación del producto, no como un archivo técnico solo para desarrolladores. La parte visual y la narrativa son fundamentales.
